# Admin dashboard

`/admin`. A signed-out visitor sees the admin login. Signed in, every screen renders inside `AdminLayout` (sidebar navigation, header, account menu, and the theme from Settings → Appearance). Access by role is described in [auth-and-roles.md](auth-and-roles.md). Marketing accounts see only Settings (the Marketing and Security tabs) and their profile.

Most list screens share the same building blocks: `AdminPageHeader`, `AdminPagination`, `AdminFilterDrawer`, `AdminViewToggle` (table or cards), `AdminActionsMenu`, `AdminImageUploader`, `MediaPicker` and `MediaDropzone`. Create and edit forms are separate routes (`/new`, `/:id/edit`) that render the same screen component with `createMode` or `editId`.

## Settings tabs (`/admin/settings`)

| Tab            | Visible to                                  | Contents                                                                                                                                                                              |
| -------------- | ------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Branding       | dashboard roles                             | Light and dark logos, favicon, page title, tagline (`site_settings`)                                                                                                                  |
| Appearance     | dashboard roles                             | Admin colour palette and dark mode, saved in this browser only (`localStorage`)                                                                                                       |
| Online payment | Admin, Super Admin                          | bKash and SSLCommerz credentials, sandbox or live, on/off. Credentials are verified with the gateway before saving. See [payments.md](payments.md)                                    |
| Marketing      | Marketing, Admin, Super Admin               | Meta Pixel and CAPI switches, dataset ID, access token, test event code. See [integrations.md](integrations.md)                                                                       |
| Security       | every admin-portal role, Marketing included | **Change password** for the signed-in account (`auth.changePassword`; the dev login shows a note instead), plus a login-notifications checkbox. The checkbox isn't saved anywhere yet |
| AI marking     | Super Admin                                 | Anthropic API key: save (validated), replace, clear, source shown (settings or environment)                                                                                           |

Secret values are never sent back to the browser. The forms show only whether a value is set and where it comes from.
